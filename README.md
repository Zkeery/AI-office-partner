# AI办公搭子

本机单用户办公工作台：帮助运营、项目及产品人员把材料整理为数据复盘、周报和调研简报初稿，支持修改、版本与多格式下载。

架构采用单逻辑 Agent 的 Plan–Execute 工作流：模型生成计划，程序按步骤执行。自研轻量 Harness 负责状态、工具与材料边界、持久化、恢复、重试和内部成本控制；它是办公应用的运行控制层，当前不作为独立通用平台交付。完整范围见[当前 PRD](docs/PRD/PRD-当前版本.md)。

更新：2026-10-05。当前真实工作台采用暖米色「贴纸创作室」：奶油纸张卡片、胶带与珊瑚粉/嫩绿点缀。`/`、`/design-lab/fusion`、`/design-lab/lilac` 使用同一套任务与报告流程。普通用户只描述任务、添加材料或链接、设置执行时间，以及查看、修改和下载结果；技术配置集中在独立的本机 `/admin` 管理页，普通导航没有入口。需求、架构、接口与验收入口见[文档索引](docs/README.md)。

当前状态：整体自查 F01–F12 的修复记录保留，覆盖材料读取、恢复与并发、模型错误和用量、内部预算，以及依赖、CI 和备份恢复。本轮移除普通界面的模型、技能、专家、token 预算、材料策略和技术统计，沿用管理员的 `LLM_*` 默认配置。旧自动化不批量启用；缺模型的规则在用户主动保存时采用管理员默认模型，开关保持原值，已有有效额度继续保留。实现和本轮验证边界见[用户界面精简](docs/阶段文档/用户界面精简.md)、[本轮验收](docs/evidence/2026-10-05-用户界面精简/验收说明.md)；前轮验收见[修复验收](docs/审查报告/2026-10-04-12项缺口修复验收.md)。

> **定位**：当前面向本机开发与自用，**不是**完整的 Vercel 一键部署方案。前端可单独静态/SSR 托管，但后端（FastAPI + 本地数据目录）需另行托管后才能上云。

## 本机启动

### 1. 依赖

- Python 3.12（使用 `backend/requirements.lock` 的完整锁定版本）
- Node.js 24 LTS（最低 22.13；含 npm）
- （可选）本机已安装桌面端依赖时可用 Electron 壳

### 2. 配置

普通任务和自动化使用维护者在本项目 `.env` 中配置的 `LLM_*` 默认模型，服务端保存具体型号供后续执行与改写沿用。独立本机管理页 `/admin` 展示模型、技能/专家、预算、材料策略、资料库授权根目录设置和技术统计；密钥仍由 `.env` 维护，不返回页面。本轮没有新增登录或服务端角色鉴权。配置和旧 API 兼容字段见[模型接入与选择](docs/模型接入与选择.md)。

```bash
cp .env.example .env
```

默认 `LLM_MOCK=1`、`SEARCH_MOCK=1`、`FEISHU_MOCK=1`，不配真实 Key 也能跑通工程路径。

`LLM_MOCK=1` 时服务端自动采用模拟模型，仅用于工程验证；普通用户无需选择模型，模拟验收不能记作真实厂商调用。
真实验收时将对应 `*_MOCK=0`，并在 `.env` 中填写自己的密钥（**不要提交 `.env`**）。

### 3. 后端（8040）

```bash
cd backend
python3.12 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --host 127.0.0.1 --port 8040 --reload
```

健康检查：打开 [http://127.0.0.1:8040/health](http://127.0.0.1:8040/health) 应看到 `{"status":"ok",...}`。

> 请在 `backend/` 目录启动，以便 `.env` 中 `DATA_DIR=./data` 落到 `backend/data/`（任务库、上传、飞书 token 等运行时文件，已由 `.gitignore` 忽略）。

### 4. 前端（3040）

另开终端：

```bash
cd frontend
npm ci
npm run dev
```

浏览器打开 [http://127.0.0.1:3040](http://127.0.0.1:3040)。

开发模式的 `frontend/next.config.js` 已通过 `allowedDevOrigins: ["127.0.0.1"]` 允许该本机地址；备用入口为 [http://localhost:3040](http://localhost:3040)。修改此配置后，确认开发服务已重启。页面能显示但导航、上传等按钮都无响应时，见操作说明中的开发来源排查。

输入任务 → 添加材料或参考链接 → 发送。页面会自动判断任务场景、生成计划并执行；费用超限时仍等待确认。自动化另设执行时间。成功后选择格式下载文件，或修改报告、查看版本。使用与故障排查见[操作说明](docs/使用与故障排查.md)。

生产模式使用 `npm run build` 后 `npm run start -- --hostname 127.0.0.1`；更新代码后需重新构建并重启前端。不要同时占用同一端口启动两份服务。

### 5. 桌面端（可选）

需已装好 backend 虚拟环境与 frontend 依赖：

```bash
cd desktop
npm install
npm start
```

说明见 [desktop/README.md](desktop/README.md)。

### 6. 测试

```bash
cd backend
source .venv/bin/activate
pytest -q
```

## 飞书接入（维护者配置）

1. 在[飞书开放平台](https://open.feishu.cn/)**自建应用**，取得 App ID / App Secret，写入本机 `.env`（勿提交仓库）。
2. 用户授权导出（导出到「我的」云文档）需配置重定向 URL，且与配置完全一致：
   - `http://127.0.0.1:8040/api/feishu/oauth/callback`
3. 建议为用户身份开通的 scopes：
   - `offline_access`
   - `drive:drive`
   - `docx:document`
4. **群通知默认关闭**（`FEISHU_NOTIFY_ON=off`），真发仍暂缓；普通用户页面已移除群通知配置与单条开关，既有状态不会因本次更新被打开。

普通用户只看到个人飞书账号连接/断开和导出操作。开放平台回调地址、应用身份导出、Webhook 和密钥维护等入口不出现在用户界面；服务端相关能力仍保留，此次未新增服务端角色鉴权。

Mock 模式下可不配飞书凭证，用本地模拟导出链路。

## 功能速览

- 任务类型：竞品调研、会议纪要、周报、邮件稿、方案模板和表格分析等，由服务端根据要求判断
- 界面：暖米色贴纸创作室、纸张卡片与彩色图标；输入框保留材料、链接和发送，首页成果与数量来自真实任务，支持手机导航
- 任务：服务端按要求自动判断场景，采用管理员默认模型；用户查看真实状态、结果与可处理的错误
- 本机管理：`/admin` 承载模型、技能/专家、预算、材料策略与技术统计，普通导航没有入口；没有新增角色鉴权
- 表格分析：完整读取 CSV/XLSX 的全部工作表，程序计算汇总、分组、月度同比环比和异常，展示真实图表
- 成品：导出 Word/Excel/PPT/Markdown；Excel 包含明细、复算公式和原生图表，PPT 包含可编辑图表与分页正文
- 报告修改：按章节或全文改写，查看版本差异、恢复旧版，冲突时阻止覆盖；合并、搜索、自动归档继续可用
- 自动化：描述重复任务、选择材料与执行时间；保留立即执行、启停、跑次历史与站内结果
- 自动化创建：不要求选择模型或填写 token 预算。内部额度默认 50,000，既有有效额度保留；提交错误显示在按钮旁，请求期间显示「创建中…」或「保存中…」
- 飞书：任务成功后导出到「我的」云文档（需用户 OAuth）

### 表格分析与报告版本

在工作台通过输入框左侧加号上传表格，说明分析目标并发送；也可从资料库「用此表分析」。完成后可切换工作表、查看图表数值和月度变化。报告下方「修改内容」可选章节或全文；「版本记录」可查看差异并恢复，恢复会另存新版本。

每次分析上限为 100,000 行、1,000,000 个数据单元格、50 张工作表、每表 512 列。每表第一条非空行作为表头，全空行忽略；超限明确报错。XLSX 的公式需先在 Excel 等软件中计算并保存，缺少缓存结果时不会按零值处理。只支持 CSV/XLSX，不执行上传表格里的公式或宏。

数值计算排除空值和非法数字，离群值保留。比例和单价类字段使用未加权均值，不能替代基于原始分子、分母的整体指标。每表自动选择一个主要指标；页面柱图展示前 12 个分组，折线展示最近 24 个有数据月份；完整计算结果与明细在 Excel 中。异常示例每表最多 100 条，并单独显示异常总数。

Excel 中的公式可复算原始明细，图表与报告是分析时的快照；修改明细后需重新上传分析。首次读取旧报告会自动建立版本记录；版本存入本机数据库，重启后保留。

前端检查：在 `frontend/` 运行 `npm run typecheck`、`npm run lint`、`npm run build`。

## 安全提示

- 密钥只放本机 `.env`，仓库仅保留 `.env.example` 占位符。
- `backend/data/`、OAuth token、通知偏好、数据库等运行时文件不应进入版本库。
- 页面会提示：任务内容会发给当前配置的模型厂商做推理。
- 若密钥曾泄露到聊天或不信任环境，请到对应控制台轮换。
