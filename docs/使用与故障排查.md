# 使用与故障排查

更新：2026-10-04。启动命令和依赖见 [README](../README.md)，模型接入见[模型接入与选择](模型接入与选择.md)。

## 从输入到文件

1. 打开 `http://127.0.0.1:3040/`。原 `/design-lab/fusion`、`/design-lab/lilac` 已接入相同真实工作台，可以继续使用。
2. 输入具体任务，按需要添加材料或参考链接，手动选择模型，再点击紫色发送按钮。每次新建都需选择模型。
3. 创建计划、上传与重新规划完成后自动执行；费用超限时页面会等待确认。执行记录可查看步骤和依据，运行中可暂停。
4. 成功后选择 Markdown、Word、Excel 或 PPT，再点击下载；「修改内容」「版本记录」用于改写、比较和恢复。个人飞书导出需先连接自己的账号。

「我的任务」可搜索与管理真实任务；「资料库」用于参考原料；「自动化」提供定时/依赖触发、立即执行、启停和跑次历史。语音尚未接入。普通页面不提供管理员接入、密钥、Webhook 或群通知配置。

## 页面能打开但操作没有结果

| 现象 | 检查与处理 |
| --- | --- |
| 仍看到「界面预览 · 示例数据」或固定销售示例 | 这是旧前端产物或旧标签页。当前 `/`、`/design-lab/fusion`、`/design-lab/lilac` 应显示「本机工作台」和真实任务，刷新页面；若仍旧，按 README 重新构建并重启前端 |
| 打开的是 `/design-lab` 四方向比较页 | 它是保留的设计研究页；回到 `/` 使用真实功能 |
| 模型列表为空或出现读取失败 | 检查后端 `/health` 和 `/api/models`；响应模型在 `items` 中，只有 `available=true` 的模型出现在菜单中。配置由维护者在本项目 `.env` 中完成 |
| 点击发送提示选择模型 | 按用户要求不预选；手动选择后再提交 |
| 表格任务提示先添加材料 | 添加 CSV/XLSX，或从资料库点击「用此表分析」；描述文字不能代替实际数据文件 |
| 报告尚未出现 | 查看任务状态及执行记录；`planning` / `running` 为处理中，`failed` 查看具体错误；成功且 `has_report=true` 才算成稿 |
| 停在费用确认 | 核对提示后由用户确认继续；不要用自动重试绕过费用确认 |
| 重启后任务暂停 | 后端会把重启时未完成的运行任务转为暂停；打开该任务点击继续 |
| 改写/恢复提示冲突 | 当前报告已有较新版本；刷新并重新查看，再决定是否修改 |
| 文件列表不存在或资料库不可用 | 可先在新任务中上传文件；授权目录由维护者配置，用户界面不显示本机目录配置表单 |

## 分层检查服务

- `http://127.0.0.1:3040/`：前端页面。
- `http://127.0.0.1:8040/health`：后端存活。
- `http://127.0.0.1:8040/api/models`：模型目录和可用配置。
- `http://127.0.0.1:8040/docs`：当前接口定义。

HTTP 200 只证明相应服务响应，不证明真实模型、材料读取或导出已成功。业务验收需要从页面创建任务，检查真实任务 ID、步骤、报告与下载文件。[本轮验收记录](evidence/真实工作流接通/验收说明.md)包含完整链路结果。

修改代码后：开发模式 `npm run dev` 自动更新；生产模式需先停止前端进程，在 `frontend/` 执行 `npm run build`，再 `npm run start -- --hostname 127.0.0.1`。后端在 `backend/` 启动，避免相对 `DATA_DIR` 指向错误目录；不要通过删除数据库或运行数据来修复页面问题。
