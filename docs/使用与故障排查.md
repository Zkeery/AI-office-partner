# 使用与故障排查

更新：2026-10-05。启动命令和依赖见 [README](../README.md)，模型接入见[模型接入与选择](模型接入与选择.md)。

当前页面保留暖米色贴纸创作室外观，普通操作围绕任务要求、材料、执行时间和成果。模型、技能/专家、token 预算、材料策略与技术统计移至独立本机 `/admin` 管理页；普通导航没有入口，密钥仍由维护者在 `.env` 中配置。本轮记录见[用户界面精简](阶段文档/用户界面精简.md)、[本轮验收](evidence/2026-10-05-用户界面精简/验收说明.md)，前轮整体自查记录见[修复验收](审查报告/2026-10-04-12项缺口修复验收.md)。

## 从输入到文件

1. 打开 `http://127.0.0.1:3040/`。原 `/design-lab/fusion`、`/design-lab/lilac` 已接入相同真实工作台，可以继续使用。
2. 输入具体任务，按需要添加材料或参考链接，再点击发送按钮；自动化另设执行时间。不需要选择模型、技能/专家或填写 token 预算。
3. 系统自动判断任务场景，创建计划、上传与重新规划完成后执行；费用超限时页面仍会等待确认。页面显示真实任务状态与结果，运行中可暂停。
4. 成功后选择 Markdown、Word、Excel 或 PPT，再点击下载；「修改内容」「版本记录」用于改写、比较和恢复。个人飞书导出需先连接自己的账号。

「我的任务」可搜索与管理真实任务；「资料库」用于参考原料；「自动化」可设置执行时间、立即执行、启停和查看跑次结果。普通页面不提供未接入的语音、管理员接入、密钥、Webhook 或群通知配置。`/admin` 是本机维护页面，本轮没有新增登录或服务端角色鉴权。

创建自动化时，只需说明任务、按需要选择材料或链接并设置时间。模型使用管理员 `LLM_*` 默认配置，内部额度默认 50,000，已有有效额度保留；这些不需要用户填写。校验或请求失败的提示显示在提交按钮旁；请求期间按钮显示「创建中…」或「保存中…」。

## 页面能打开但操作没有结果

| 现象 | 检查与处理 |
| --- | --- |
| 页面能显示，但导航、发送等按钮都无响应，并一直显示「正在读取任务」 | 先打开 `http://localhost:3040/` 对照。若备用入口可操作，检查前端日志是否出现 `Blocked cross-origin request`，以及浏览器是否出现 `/_next/hmr` WebSocket 连接失败。本项目已在 `frontend/next.config.js` 设置 `allowedDevOrigins: ["127.0.0.1"]`；确认运行的是本项目服务，重启开发服务后刷新原地址 |
| 仍看到「界面预览 · 示例数据」或固定销售示例 | 这是旧前端产物或旧标签页。当前 `/`、`/design-lab/fusion`、`/design-lab/lilac` 应显示「本机工作台」和真实任务，刷新页面；若仍旧，按 README 重新构建并重启前端 |
| 如何确认当前贴纸外观仍是真实工作台 | 地址使用上述真实入口；首页成果来自实际任务，可输入任务、添加材料并发送。`/design-lab?style=studio&flavor=collage` 仅供比较旧设计，不是业务入口 |
| 打开的是 `/design-lab` 四方向比较页 | 它是保留的设计研究页；回到 `/` 使用真实功能 |
| 提示运行配置不可用 | 维护者检查后端 `/health`、本项目 `.env` 中的 `LLM_*` 和 `/admin` 配置状态；普通用户无需补选模型或填写密钥。配置修改后重启后端 |
| 表格任务提示先添加材料 | 添加 CSV/XLSX，或从资料库点击「用此表分析」；描述文字不能代替实际数据文件 |
| 已移除表格，准备改为普通文稿 | 修改任务要求后发送，系统根据当前要求和材料重新判断，不应被已移除的表格阻断 |
| 报告尚未出现 | 查看任务状态与错误提示；`planning` / `running` 为处理中，`failed` 查看具体错误；成功且 `has_report=true` 才算成稿 |
| 停在费用确认 | 核对提示后由用户确认继续；不要用自动重试绕过费用确认 |
| 重启后任务暂停 | 后端会把重启时未完成的运行任务转为暂停；打开该任务点击继续 |
| 重启后原来正在规划的任务失败 | 显示 PLANNING_INTERRUPTED，原输入和材料保留；打开任务重新规划，不会永久停在规划中 |
| 文档超限或没有可提取文字 | 单文档最多 60,000 字符、任务文档合计 90,000；超限需拆分任务。DOCX 包含表格；扫描 PDF 无 OCR，应先提供可提取的文本版本。模型仍可能遗漏事实，交付前核对正文 |
| 重复上传相同名称的资料库文件 | 自动追加独立后缀保留每一份，既有文件不被覆盖 |
| 自动化显示暂停或中断 | 这不是成功。可以查看对应任务；暂停任务可手动继续，原跑次保留当时状态，后续人工操作记录在任务用量中 |
| 旧自动化需要重新保存 | 打开并保存任务要求、材料和时间，服务端为缺模型的规则采用管理员默认，原开关保持不变；不要求选择模型或填写预算，也不会批量开启历史规则 |
| 点击「创建自动化」或「保存自动化」后未成功 | 查看提交按钮旁的具体错误；核对任务要求、材料与执行时间。请求期间显示「创建中…」或「保存中…」，失败后可按提示修正重试；运行配置错误由维护者处理 |
| 自动化提示正在运行 | 同一规则已有未结束跑次；等待或打开对应任务处理，不重复触发或删除规则 |
| 自动化提示运行额度不足 | 本次执行触及内部额度保护并停止；任务与结果保留。维护者在 `/admin` 检查技术统计与额度，普通用户无需填写 token 数值 |
| 模型权限或额度错误 | LLM_AUTH_FAILED / LLM_QUOTA_EXCEEDED 不会自动重试或换模型；检查该厂商凭据、权限或额度 |
| 模型超时、限流或服务暂时错误 | 连接失败、超时、408/429/5xx 有最多 3 次请求尝试；仍失败会显示具体错误，可稍后手动重试 |
| 改写/恢复提示冲突 | 当前报告已有较新版本；刷新并重新查看，再决定是否修改 |
| 文件列表不存在或资料库不可用 | 可先在新任务中上传文件；维护者在 `/admin` 设置资料库授权根目录，普通用户只浏览、上传、选择资料，不显示本机技术目录路径 |

## 分层检查服务

- `http://127.0.0.1:3040/`：前端页面；开发模式备用入口为 `http://localhost:3040/`。
- `http://127.0.0.1:8040/health`：后端存活。
- `http://127.0.0.1:8040/health` 的 `default_model_id` / `default_schedule_token_budget`：默认配置诊断。
- `http://127.0.0.1:8040/api/models`：管理模型目录和可用配置。
- `http://127.0.0.1:8040/docs`：当前接口定义。

HTTP 200 只证明相应服务响应，不证明真实模型、材料读取或导出已成功。业务验收需要从页面创建任务，检查真实任务 ID、步骤、报告与下载文件。[本轮验收记录](evidence/真实工作流接通/验收说明.md)包含完整链路结果。

任务只读取本次明确添加的材料；资料库目录授权不代表整库会进入模型。普通自动化表单选择材料和参考链接，材料版本策略与上游依赖由维护者管理，输入清单保存在每个跑次。内部额度和技术用量在管理页查看，必要的费用确认仍保留；估算金额不能当作厂商实际账单。

修改代码后：开发模式 `npm run dev` 自动更新；修改 `next.config.js` 后，确认开发服务已重启。生产模式需先停止前端进程，在 `frontend/` 执行 `npm run build`，再 `npm run start -- --hostname 127.0.0.1`。后端在 `backend/` 启动，避免相对 `DATA_DIR` 指向错误目录；不要通过删除数据库或运行数据来修复页面问题。

## 备份与恢复

先正常停止后端，再在项目根目录执行（输出目录必须不存在）：

```bash
backend/.venv/bin/python scripts/backup_restore.py backup --data-dir backend/data --output backups/manual-backup
backend/.venv/bin/python scripts/backup_restore.py restore --backup backups/manual-backup --target .runtime/restored-data
```

工具保存数据库与运行目录内的材料、成果、版本和自动化快照，恢复时校验哈希、SQLite 完整性并重定位文件路径。恢复目标必须是新目录，禁止覆盖原数据。恢复副本的自动化默认关闭，先检查资料和结果，再配置 DATA_DIR 切换。外部资料库需要备份时，显式在 backup 命令添加 `--workspace-root /绝对/资料库路径`；默认不扫描或复制外部目录。项目 `.env` 不在数据备份中，需单独管理配置。数据备份可能含 OAuth 凭据，目录/文件使用 0700/0600 权限并排除 Git。

后端每个数据目录只允许一个服务进程，不使用 `--workers 2` 等多 worker 配置；备份工具遇到服务锁时拒绝操作。服务停止期间不执行定时任务。
