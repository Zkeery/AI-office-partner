## 产品与交互

面向个人本地办公，涵盖调研、写作、数据分析及多格式交付。用户描述任务、添加材料并发送，自动化另设时间；服务端复用 `detect_scene` 判断场景并采用管理员 `LLM_*` 默认模型，前端自动接续计划与执行，费用超限保留确认。模型、技能、专家、预算与材料策略不要求普通用户选择，结果支持修改与版本恢复。

当前是单逻辑 Agent 的 Plan–Execute 工作流：LLM 生成结构化计划，程序校验并按步骤执行工具，再基于真实结果组织成果。专家是场景化 Prompt 角色，复用同一任务控制链。自研轻量 Harness 为底层控制层，承担状态、持久化、工具与材料约束、暂停恢复、有限重试和内部成本控制；产品仍是办公成果应用，Harness 当前不作为独立平台提供。

暖米色贴纸创作室复用正式业务逻辑，包含手机抽屉导航、附件、参考链接、真实成果、任务搜索、资料库及自动化。独立本机 `/admin` 集中展示模型、技能/专家、预算、材料策略、资料库授权根目录设置和技术统计，普通导航无入口；普通资料库仅浏览、上传和选择材料，不展示本机技术目录路径。未接入的语音不在普通页面展示。

## 适配边界

- 不新增云基础设施、跨项目凭据或共享数据存储。当前仍是本机单用户。
- 保留费用软闸门、输入和模型输出校验、真实工具结果、持久化与版本冲突保护。
- Harness 继续作为办公成果应用的内部控制层，不单独提供平台；本次只统一现行定位，不增加多 Agent 协作或执行中自主重规划。材料变化后的重规划和用户发起的重试、改写保留现有行为。
- 普通用户界面不提供技术或管理员配置；`/admin` 仅为本机独立维护页面，没有新增登录或服务端角色鉴权。密钥仍由本项目 `.env` 管理，不返回页面。
- 旧缺模型自动化不批量启用；用户主动保存时采用管理员默认且保持原开关，仅缺额度已有模型的规则可内部默认。旧 API 显式字段与有效历史额度保留，不倒填历史实际型号和用量。
- 不引入通用浏览器 Agent、多 Agent 团队、RAG 向量库、通用插件商店或语音识别。
- 不重跑未配置的蓝图模型管线；2026-09-27 的手册分析来源保留为历史事实，未将其写作独立模型审核。
- GPT、通义千问和豆包的接口路由已测试，但缺少本项目实际凭据，未宣称真实接通。型号、端点与兼容条件见[模型文档](../模型接入与选择.md)。
