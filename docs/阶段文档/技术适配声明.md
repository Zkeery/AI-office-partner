## 1. 产品形态判断

- **产品类型与核心任务**：个人本地用的 AI 办公搭子——自然语言下调研任务，拆步骤执行，产出可交差的 Markdown 调研报告（对标 WorkBuddy 方向，MVP 只做报告主链路）。
- **核心交互**：**分阶段确认** + **动态工具调用**（先计划后执行；执行中检索/读材料/写报告；可暂停与改计划）。
- **开发路径**：**纵向切片（路径 B）**。理由：计划确认、进度观察、报告阅读与下载本身就是验收体验，不能把界面留到最后当壳。
- **当前阶段范围**：阶段 1 只出适配结论与架构，不写业务代码。下一阶段（阶段 2）做后端 MVP + 最小可验收 Web 页：下任务 → 计划确认 → 联网检索 → Markdown 报告与下载；本机持久化与重启恢复。

## 2. 采用的默认方案

| 方案 | 采用原因 |
| --- | --- |
| Python 3.12 + FastAPI | 手册默认后端；本机端口 8040 |
| Pydantic | 校验 API 入参与模型结构化输出（计划步骤、报告元数据） |
| pytest | 自动化测试默认 |
| Web（Next.js + TypeScript + Tailwind） | PRD 未指定桌面/App；默认 Web；端口 3040；纵向切片需要可见界面 |
| Git + 项目内 `.env` | 密钥外置（强制底线） |
| 模型：用户自备 Key，官方/兼容 SDK | PRD D4；不锁定厂商 |
| SQLite + SQLAlchemy（或等价薄封装） | 任务/计划/步骤/事件多实体，需重启恢复与按任务删除 |

## 5. 强制底线检查

- **密钥与隐私**：✅ 计划通过——Key 只进项目 `.env`；前端不持有；界面告知正文将发往当前模型厂商；产品不当训练数据（D7）
- **数据与任务可恢复**：✅ 计划通过——任务/计划/步骤/确认点入 SQLite；产物落盘；重启可恢复
- **输入输出校验**：✅ 计划通过——上传白名单与大小；模型输出结构校验；失败有限重试
- **错误与日志边界**：✅ 计划通过——`{"error":{"code","message"}}`；SSE `done`/`error`；日志不记 Key 与完整正文
- **高风险动作**：✅ 计划通过——执行计划、超费用软上限由代码闸门；MVP 无对外发送
- **测试与真实模型验收**：mock 测试先行；真实 Key 由你提供后做冒烟；D2 用 5～10 条真任务打分（待样例打分，不阻塞开工）

## 产品经理只需确认三件事

1. **理解是否正确**：个人本地用；第一版只做「说话下调研任务 → 计划确认 → 联网检索 → Markdown 报告可下载」；技能/专家随后，定时任务和更多连接器更后。
2. **有没有多出来的费用/平台/范围**：无新增云资源；只用你自备的模型 Key + 公网检索；不上云、不办企业认证。
3. **被暂缓的能力是否影响你下一阶段验收**：不影响。Word、本地文件夹、技能/专家、定时、腾讯生态、桌面 App 都不进阶段 2 验收。
