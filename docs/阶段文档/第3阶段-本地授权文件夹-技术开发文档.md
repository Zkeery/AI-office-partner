# 第 3 阶段技术开发文档｜本地授权文件夹

> 配套：PRD §5 紧随项「授权本地文件夹读写」、第 1/2 阶段文档。  
> **只做**：用户指定一个本机目录为工作区；可浏览/读取；可将报告写入该目录（须确认）。  
> **不做**：任意盘符乱逛、删除文件、技能/专家、定时任务、系统文件夹默认开放。

---

## 一、阶段目标

### 交付
1. 设置「授权工作区根目录」（绝对路径，必须已存在且为目录）
2. 在授权范围内：列出子项、读取文本文件（扩展名白名单）
3. 任务成功后：一键「导出报告到工作区」（Markdown，可选同时 docx）；**写入前二次确认**
4. 执行任务时：若已配置工作区，自动把工作区内文本材料摘要纳入调研参考（只读）

### 明确不做
- 删除/移动/重命名用户文件  
- 越权访问根目录之外  
- 图形化系统文件选择器（本阶段用路径输入；macOS 原生对话框后置）  
- 技能/专家  

### 验收
- 填一个测试文件夹路径并保存成功  
- 能看到目录列表、打开一个 `.md/.txt` 预览  
- 导出报告须点确认后，文件夹里出现文件  
- 路径穿越（`../`）被拒绝  
- mock 测试覆盖上述安全与导出  

---

## 二、适配摘要
- 强制底线：路径规范化 + 前缀校验；写操作人工确认；不做删除  
- 配置落盘：`data/workspace.json`（非密钥）

---

## 三、配置
`.env.example` 可增加可选默认：
```bash
# 可选；也可用界面设置，写入 data/workspace.json
LOCAL_WORKSPACE_ROOT=
```

界面设置优先于空的环境变量。

---

## 四、API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/workspace` | `{root, configured}` |
| PUT | `/api/workspace` | body `{root}` 校验存在且为目录 |
| GET | `/api/workspace/entries?rel=` | 列出相对路径下条目 |
| GET | `/api/workspace/file?rel=` | 读文本，≤ 512KB |
| POST | `/api/workspace/export` | `{task_id, formats:["md","docx"], confirm:true, subdir?}` |

错误码：`WORKSPACE_NOT_SET` / `WORKSPACE_INVALID` / `PATH_DENIED` / `WRITE_CONFIRM_REQUIRED` / `FILE_TOO_LARGE` / `FILE_TYPE_NOT_ALLOWED`

---

## 五、路径安全
- `resolve(root / rel).resolve()` 必须 `startswith(root.resolve())`  
- 拒绝 symlink 逃逸（resolve 后仍检查）  
- 读白名单：`.txt .md .markdown .csv .json .docx`（docx 仅元数据/跳过或抽文本；本阶段列表可见，读文本以纯文本类为主，docx 可读 excerpt）  
- 写：仅允许创建/覆盖 `report*.md` / `report*.docx` 到工作区（或 `subdir`），文件名经安全清洗  

---

## 六、Agent
- 计划步骤 `tool_hint` 含 `local_workspace` 或步骤名含「本地」：只读汇总工作区文本（限前 N 个文件、总字符上限）  
- 不自动写入工作区；写入只走导出 API + 确认  

---

## 七、前端
- 侧栏或顶区：「工作区路径」输入 + 保存  
- 简单文件列表 + 点击预览  
- 报告区：「导出到工作区」→ 确认对话框 → 调用 export  

---

## 八、测试
1. 未设置 workspace → list 返回明确错误  
2. 设置临时目录成功  
3. `rel=../etc` → PATH_DENIED  
4. 写入无 confirm → WRITE_CONFIRM_REQUIRED  
5. confirm 后文件存在  
6. 任务执行可读到工作区文本（mock）
