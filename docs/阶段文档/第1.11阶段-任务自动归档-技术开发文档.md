# 第 1.11 阶段技术开发文档｜任务自动归档

> 文档同步说明（2026-10-04）：本文为对应阶段的历史设计/验收记录；当前界面、功能范围和操作方式以[当前 PRD](../PRD/PRD-当前版本.md)、[真实工作流实现](融合界面与真实工作流.md)为准。新建任务和自动化均必填 `model_id`，旧无模型参数示例请按[当前 API](../API接口.md)更新后使用。

> 产品决策：选 **C**——任务过多时自动归档，可手动找回。  
> 状态：**已开发，待产品经理点验**（2026-09-28）。

## 一、阶段目标
- 交付：侧栏默认不堆满历史任务；超出规则的任务标为 `archived` 并从默认列表隐藏；可「显示已归档」并「恢复」。
- 不做：物理删除、登录账号、跨设备同步。

## 二、产品默认规则
1. **条数**：非 `merged` / `archived` 的任务超过 **8** 条时，把最旧的可归档任务（`succeeded` / `failed` / `paused` / `plan_ready`）标为归档，直到 ≤8。不归档 `running` / `planning`。
2. **天数**：上述可归档状态且 `updated_at` 超过 **7 天（一周）**的，即使未超 8 条也归档。
3. 触发时机：列表查询、创建任务后自动跑一遍（幂等）。
4. 恢复：`POST /api/tasks/{id}/unarchive` → 有报告则 `succeeded`，否则 `plan_ready`。

## 三、改动
- `config`：`task_keep_recent=8`、`task_archive_after_days=7`（可用环境变量 `TASK_KEEP_RECENT` / `TASK_ARCHIVE_AFTER_DAYS`）
- `tasks` 服务：`auto_archive_tasks` / `unarchive_task`；`list_tasks(include_archived=)`；时间比较统一 `_as_utc`
- API：`GET /api/tasks?include_archived=`；`POST /api/tasks/{id}/unarchive`
- 前端：场景卡等宽三列网格；归档自动静默收起，不展示「显示已归档」入口（后端仍保留 unarchive API）
- 测试：`tests/test_archive.py`（条数阈值 + 天数阈值）
