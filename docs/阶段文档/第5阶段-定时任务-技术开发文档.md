# 第 5 阶段技术开发文档｜定时任务

> 文档同步说明（2026-10-04）：本文为对应阶段的历史设计/验收记录；当前界面、功能范围和操作方式以[当前 PRD](../PRD/PRD-当前版本.md)、[真实工作流实现](融合界面与真实工作流.md)为准。新建任务和自动化均必填 `model_id`，旧无模型参数示例请按[当前 API](../API接口.md)更新后使用。

> PRD 后置项优先落地。到点自动创建调研任务并执行（费用超软上限则跳过并记事件）。  
> **不做**：复杂 crontab 表达式编辑器、分布式调度、邮件推送结果。

---

## 一、目标
1. 创建/启停/删除定时任务：名称、prompt、可选 skill/expert、间隔分钟数  
2. 后台每 30s 扫一次到期项 → 创建任务并自动确认执行（费用闸门仍生效）  
3. 前端可管理列表、看上次运行关联的 task_id  
4. 持久化到 SQLite，重启不丢  

## 二、数据 `schedules`
`id, name, prompt, skill_id, expert_id, interval_minutes, enabled, next_run_at, last_run_at, last_task_id, created_at, updated_at`

## 三、API
| 方法 | 路径 |
| --- | --- |
| GET/POST | `/api/schedules` |
| PATCH | `/api/schedules/{id}`（改 enabled / 字段） |
| DELETE | `/api/schedules/{id}` |
| POST | `/api/schedules/{id}/run-now`（立即触发一次，测用） |

## 四、规则
- `interval_minutes` 最小 1（测试可用）；产品默认建议 ≥60  
- 到期：创建 task（带 skill/expert）→ confirm（超费用则写 last 错误、顺延 next_run）  
- 写入工作区：**不**自动；用户事后导出  

## 五、测试
创建 → run-now → 产生 task；禁用后不再触发；重启后 schedule 仍在  

## 六、验收
- [ ] 能新建「每 N 分钟」的定时调研  
- [ ] 点「立即跑一次」能出任务  
- [ ] 关闭开关后不再自动跑
