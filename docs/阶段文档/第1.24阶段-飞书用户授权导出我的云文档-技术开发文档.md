### 1.3 产品语境

- 1.8 产品事实未变：当前导出是应用身份，不是用户「我的」云空间。
- 1.23 产品选切曾把「用户授权写我的文档」标为备选 A；现选定为本刀。
- 本机产品：后端默认 `127.0.0.1:8040`，前端 `3040`；OAuth 回调天然落在本机地址。
- 群通知保持止血：不因本刀改回打开；不做真发群验收。

## 二、阶段目标

在**不推翻本地单人定位、不引入飞书登录本应用**的前提下，让用户完成一次飞书用户授权后，「导出到飞书」创建的云文档出现在**该用户自己的飞书云空间**（「我的」文档），并可继续复制/打开链接。

一句话：**授权一次 → 导出进我自己的飞书文档。**

## 三、非目标

- **不做**用飞书账号登录本应用（会话、登出、未登录拦接口、多用户账号体系）。
- **不做**飞书群真发产品验收；不重开 1.23 真发；不默认打开群通知。
- **不做**腾讯文档 / 钉钉 / 企微对等集成。
- **不做**飞书文档双向同步编辑、权限细配 UI、自动分享给指定同事。
- **不做**把真实 `APP_SECRET` / OAuth client secret / user token 写进文档、仓库或聊天。
- **本轮不写功能代码**（主助手另派实现后再动代码）。
- 不改坏第 12 / 1.8 已有 mock 导出与链接复制；不改坏 1.23 群通知工程路径（可保持默认关）。

## 四、切片建议（实现时一次一刀）

### 4.1 推荐第一实现切片（最小可验）

**产品一句话**  
点「连接飞书账号」→ 浏览器同意授权 → 回调本机成功 → 状态显示「已连接」；此后「导出到飞书」用用户 token 建文档（mock 下可模拟已授权，不打断工程验收）。

**建议范围（可交付）**

1. **OAuth 授权码（本机回调）**  
   - 开放平台登记 redirect：`http://127.0.0.1:8040/api/feishu/oauth/callback`（端口以实配为准）。  
   - API 草案：`GET /api/feishu/oauth/start`（302 到飞书授权页）、`GET /api/feishu/oauth/callback`、`GET /api/feishu/oauth/status`、`POST /api/feishu/oauth/disconnect`。  
2. **Token 落盘**  
   - 存 `user_access_token` / `refresh_token` / 过期时间于本机安全位置（优先系统钥匙串或本机加密文件；至少 **不进 git**、不进 `.env` 明文提交）。  
   - 刷新失败 → 状态变「需重新授权」，导出给出可读提示。  
3. **导出改走用户身份**  
   - `export_markdown_to_feishu`：已授权则用 `user_access_token` 创建 Docx；未授权则引导授权（**产品确认**是否保留应用凭证 fallback，见第七节）。  
   - Mock：`FEISHU_MOCK=1` 时可设「模拟已授权用户」，仍返回可复制 mock 链接。  
4. **UI**  
   - 任务成功区「导出到飞书」旁或设置区：连接状态 +「去授权」/「断开」。  
   - 未授权点导出：可读提示并跳转授权，不静默失败。  
5. **pytest**  
   - mock 授权态导出成功；未授权拦截/引导码；回调失败可读错误；token 不出现在日志全文。

## 六、风险与依赖

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| OAuth 权限 / scope | 开放平台未开通云文档写权限则创建失败 | 文档写清所需 scope；错误码可读；mock 保底工程 |
| Redirect URI | 须与开放平台登记完全一致；本机 `127.0.0.1` 可能被租户策略限制 | 仅本机自用说明；桌面端用系统浏览器完成授权 |
| Token 存储 | user/refresh token 泄露面大于应用 secret | 不进 git；本机加密/钥匙串；日志脱敏；支持断开吊销本地副本 |
| Token 刷新 | 过期未刷导致导出突然失败 | 导出前检查过期；失败引导重授权 |
| 与应用导出并存 | 用户 token vs tenant token 两套身份易混 | UI 写清「我的文档（已授权）」；产品定是否保留应用 fallback |
| 范围膨胀 | 顺手做登录本应用或重开群真发 | **本刀只做用户授权写文档** |
| 无公网 | 不影响本机回调出站 OAuth；事件订阅仍不做 | 与 1.23 入站事件无关 |

**依赖**：第 12 / 1.8 导出与链接链路稳定；现有 `FEISHU_APP_ID`/`SECRET`（OAuth 应用同一套或另配，以实现时开放平台配置为准）。  
**不依赖**：群通知真发、上云、正式账号体系。
