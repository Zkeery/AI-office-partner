# 第 1.4 阶段技术开发文档｜更多专家包

> 配套：`docs/PRD/PRD-1.1.md`、通用技术栈手册。  
> 只覆盖专家/技能/场景扩面；不提前做多形态打磨。  
> 状态：**已实现，待产品经理验收**（2026-09-28）。

## 一、阶段目标
- 交付：新增 3 组「场景 + 技能 + 专家」——政策速读、对客话术、项目推进。
- 产物：catalog JSON、场景识别关键词、mock 计划分支、测试。
- 不做：真实政策库/客服工单系统；多形态默认下载（1.5）；货架交互大改（1.3 已完成）。

## 二、技术适配摘要
- 沿用目录驱动：扩 `scenes.json` / `skills.json` / `experts.json` + `llm.py` mock。
- 前端场景卡与货架自动读取 API，无需新页面。

## 三、技术栈与模型
- 同既有栈；mock 模式可验计划结构。

## 四、环境与配置
- 无新增；后端若未 `--reload` 需重启以清 catalog 缓存（或进程 reload）。

## 五、项目结构
- `backend/app/catalog/scenes.json`：+policy_brief / customer_reply / project_update
- `backend/app/catalog/skills.json`：同上 id 技能
- `backend/app/catalog/experts.json`：policy_reader / customer_voice / project_coordinator
- `backend/app/services/llm.py`：对应 mock 计划
- `backend/tests/test_scenes.py`：列表、识别、计划用例

## 六、数据
- 无新持久化表；目录为静态 JSON。

## 七、API
- 复用 `/api/scenes`、`/api/skills`、`/api/experts`、`/api/scenes/detect`、`POST /api/tasks`。

## 八、Prompt
- 各技能 `plan_hint` / `report_hint`；专家 `persona`；mock 与真实共用目录字段。

## 九、界面
- 新建页场景卡自动多 3 张；货架专家/技能计数增加。

## 十、测试
- mock：`test_list_scenes`、`test_list_experts_and_skills_expanded`、`test_detect_scene_policy`、`test_policy_skill_plan` 等。
- 真实冒烟：待验（需 Key）。

## 十一、验收清单
- [ ] 新建页可见「政策速读」「对客话术」「项目推进」
- [ ] 打开货架可见对应专家（政策解读助手 / 对客沟通专家 / 项目推进助手）
- [ ] 点「政策速读」生成计划，步骤含政策相关内容
- [ ] 输入含「政策速读」能识别到该场景

## 十二、风险
- 关键词冲突时检测可能抢场景；优先长词匹配已有规则。

## 十三、交接
- 下一阶段（1.5 多形态）：按 `skill_id` 推荐 Word/Excel/PPT/Markdown 下载入口。
