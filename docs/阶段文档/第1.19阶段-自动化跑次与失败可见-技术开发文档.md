# 第 1.19 阶段技术开发文档｜自动化跑次可见 + 失败可跟

> 承接：1.18 已把「定时」改成「自动化」；本刀让跑次与失败在列表里看得见、点得进。  
> 状态：**已通过**（2026-09-29）。

## 一、阶段目标
- 列表展示 `last_run_at`（上次跑时间）。
- `last_error` 升格为独立可见列，不再只埋在名称下 truncate。
- 「最近一次」可点进对应任务；失败时同样可点（依赖 `last_task_id`）。
- 调度创建了任务但执行失败时：写入 schedule.`last_error`，保留 `last_task_id`，并更新 `last_run_at`。
- AppError（如计划失败）同样写入 `last_error` 并更新 `last_run_at`。

## 二、改动
- `backend/app/services/schedules.py`：`trigger_schedule` 对齐任务真实结果（不再在 task failed 后清空 `last_error`）。
- `frontend/app/page.tsx`：自动化表增加「上次跑」「最近一次」列；错误独立展示。
- `frontend/app/globals.css`：`.sched-last-error` 多行可见（最多约 3 行）。
- `backend/tests/test_schedules.py`：成功字段齐全、AppError、任务执行失败三条用例。
- 不做：crontab、邮件外发、事件触发、跑次历史长列表、新复杂 API。

- [x] 任务执行失败后 schedule.`last_error` 非空且 `last_task_id` 对应 failed 任务
