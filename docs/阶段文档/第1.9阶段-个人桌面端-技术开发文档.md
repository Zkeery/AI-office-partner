# 第 1.9 阶段技术开发文档｜个人桌面端（壳）

> 配套：`docs/PRD/PRD-1.1.md`（决策 4B）、产品经理选定「开发 B」。  
> 状态：**已开发，待产品经理验收**（2026-09-28）。

## 一、阶段目标
- 交付：本机可双击/一条命令打开的**桌面窗口**，自动拉起后端 8040 + 前端 3040（若已在跑则复用），界面仍是现有 Web 产品。
- 产物：`desktop/` Electron 壳 + 启动说明；阶段文档。
- 验收：见第十一节。
- 不做：App Store 上架、自动更新、安装包公证、Windows/Linux 首发打磨、业务功能重写、飞书 OAuth。

## 二、技术适配摘要
- **推荐方案：Electron 壳 + 复用现有 FastAPI / Next.js**（不重做界面）。
- 理由：改动小、与现网一致；关掉窗口时尽量停掉本壳拉起的子进程。
- 费用：无新增云资源；仅本机 Node/Electron。
- 开发路径：纵向切片——先能开窗用，再谈安装包。

## 三、技术栈
- Electron（桌面窗口）
- 子进程：`backend/.venv` 的 uvicorn；`frontend` 的 `next dev`（开发壳）或已 `next build` 后的 `next start`
- 端口仍以 `project.json`：8040 / 3040

## 四、环境
- 需已具备：Python venv、`npm install`、项目 `.env`
- 桌面目录自有 `node_modules`（Electron）

## 五、项目结构
- `desktop/package.json` / `desktop/main.js` / `desktop/preload.js`（可选）
- `desktop/README.md`：照着开
- 根 `README.md`：补「桌面端」一节

## 六、行为
1. 启动时探测 `http://127.0.0.1:8040/health`；不通则启动 uvicorn。
2. 探测 `http://127.0.0.1:3040`；不通则启动 Next（默认 `next dev`，可用环境变量切 `start`）。
3. 打开无边框干扰的窗口加载前端；标题「AI办公搭子」。
4. 退出应用时，仅终止**本进程拉起**的子进程（不杀用户原本已开的服务——若复用则不管）。

## 七、API
- 无新业务 API；复用 `/health`。

## 八、风险
- 首次需本机已装好依赖；未 build 时用 `next dev` 即可验收。
- macOS 可能拦截未签名 Electron——本阶段用开发方式启动，不强制公证。

## 九、测试
- 手工：`cd desktop && npm install && npm start` → 出现窗口且能新建任务。
- 后端既有 pytest 不受影响。

## 十、验收清单
- [x] 一条命令能打开桌面窗口（`cd desktop && npm start`；已冒烟复用本机 8040/3040）
- [ ] 窗口内可完成「新建 → 计划 →（可选）看报告」（待产品经理点验）
- [x] 关闭窗口后，由壳拉起的子进程退出；复用外部服务时不杀（代码已具备）
- [x] README 有照着做步骤
- [x] 无密钥进仓库
