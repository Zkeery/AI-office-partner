## 二、阶段目标

在**不推翻本地单人定位**的前提下，把「飞书」从「只能用应用凭证导出一篇云文档」推进到产品可选的下一步切片之一，并先立文档、等产品选切：

1. **跑完把结果发到飞书群/会话**（机器人出站通知），或  
2. **用飞书用户授权，导出写进「我的」云文档**（用户 OAuth 写盘），或  
3. **用飞书账号登录本应用**（把飞书身份当作应用登录）——代价最大，见非目标与备选说明。

本阶段**一次只切一刀**；未选中的方向继续后置。

## 三、非目标

- **不做**腾讯文档 / 钉钉 / 企微对等集成。
- **不做**飞书文档双向同步编辑、权限细配 UI、自动分享给指定同事（除非选中的切片验收明确要求「发到某群」）。
- **不做**正式多用户账号体系、邀请码上云登录（见上线方案摘要-暂缓）。
- **不做**把真实 `APP_SECRET` / OAuth client secret / user token 写进文档、仓库或聊天。
- ~~**不在本轮写任何功能代码**~~（产品已选 4.1 后已实现第一刀）。  
- 不改坏第 12 / 1.8 已有 mock 导出与链接复制行为。

## 四、候选切片（产品话术）

### 4.1 推荐第一刀：跑完把结果发到飞书群

**产品一句话**  
自动化或任务跑完后，可把「成功/失败摘要 + 报告链接（若有）」发到指定飞书群（或指定会话）。

**为何推荐**  
- 紧接 1.21 站内通知、1.22 事件触发：用户下一问常常是「群里能不能看到」。  
- 仍可用**应用/机器人凭证**发消息，不必先上完整「飞书登录本应用」。  
- 验收场景清晰：开自动化 → 跑完 → 群里出现一条消息。  
- 与现有 `schedule_runs` / notices 可并存（站内 + 飞书可选）。

**第一刀范围建议（可交付）**  
1. 配置：沿用或扩展 `.env` 中的应用凭证；增加机器人发消息所需项（如目标 `chat_id` / 接收对象；**密钥只进本机 `.env`，示例进 `.env.example` 空值**）。  
2. 触发点：自动化跑次结束（至少失败，成功可开关）或任务 `succeeded` 后可选「通知飞书」。  
3. 消息内容：短摘要 + 本机任务页提示或已有飞书文档链接（若刚导出）；**不**在第一刀做富交互卡片编排大工程。  
4. Mock：`FEISHU_MOCK=1` 时只记本地发送记录、不调真实 IM。  
5. UI：自动化详情或设置里「飞书通知：开/关 + 目标说明」；失败时站内 notices 仍可见。

**相对代价**  
- 需在飞书开放平台建应用/机器人、拿会话 ID；本机无公网时，**入站事件订阅**难做——第一刀建议只做出站发消息，不接飞书侧回调事件。

### 4.2 备选 A：用飞书用户授权，导出写进「我的」云文档

**产品一句话**  
点「导出到飞书」前先「用飞书授权」，文档出现在**我登录的那个飞书账号**云空间，而不是应用公共空间。

**何时选**  
- 产品仍卡在 1.8 反馈：「要进我自己的文档」，且群通知暂时不急。  
- 能接受本机 OAuth 回调（见风险）与 token 落盘。

**第一刀范围建议**  
1. 标准 OAuth 授权码：浏览器打开飞书授权页 → 回调本机 `http://127.0.0.1:8040/.../callback`（端口以实配为准）。  
2. 存 `user_access_token` / refresh（加密或系统钥匙串优先；至少不进 git）。  
3. 导出改用用户 token 创建 Docx；未授权时引导授权，保留现有应用凭证路径作 fallback 或明确下线其一（产品定）。  
4. Mock 下可模拟「已授权用户」不打断工程验收。

**相对推荐刀的代价**  
- OAuth 凭证、redirect URI、token 刷新与吊销；桌面端/浏览器弹窗体验；比「发一条群消息」链路长。

### 4.3 备选 B：用飞书账号登录本应用

**产品一句话**  
打开 AI 办公搭子要用飞书扫码/授权登录，而不是现在的本机免登录。

**何时选**  
- 明确要多设备、多人或准备上云分享；本地单人 MVP **通常不必先做**。

**为何不推荐作第一刀**  
- 与 PRD「MVP 单人本机、不做正式账号体系」冲突面大。  
- 要做会话、登出、未登录拦接口；改动面远超「通知」或「导出身份」。  
- 若只为「导出到我的文档」，备选 A 足够，不必上升为应用登录。

## 五、推荐实现顺序（若产品未另定）

**先做 4.1（群/会话通知），备选再考虑 4.2（用户 OAuth 写文档）；4.3 默认后置。**

| 顺序 | 切片 | 理由 |
| --- | --- | --- |
| 1 | 跑完发到飞书群 | 贴现自动化价值；可不碰用户 OAuth；mock 好验 |
| 2 | 用户授权写「我的」文档 | 补齐 1.8 产品事实；依赖回调与 token |
| 后置 | 飞书登录本应用 | 账号体系级；本地单人非刚需 |

产品也可**只选 4.2、不做 4.1**——以书面选切为准；本文推荐仅供拍板。

## 七、风险与依赖

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| OAuth 凭证泄露 | `APP_SECRET`、client secret、user token 进仓/进聊天 | 只写本机 `.env`；文档与 commit 禁止实值；曾泄露则控制台轮换 |
| 本机回调 | 飞书要求配置 redirect URI；本机为 `127.0.0.1`；部分租户策略限制 | 开放平台登记本机回调；第一刀写清「仅本机自用」；桌面端可系统浏览器完成授权 |
| 无公网 | 飞书**事件订阅入站**打不到本机 | 通知刀先做出站发消息；入站事件另议或配合已有 Webhook |
| 群 ID / 权限 | 机器人未进群或缺 IM 权限导致发送失败 | 配置说明 + 明确错误码；mock 保底工程验收 |
| 与应用导出并存 | 用户 token vs tenant token 两套身份易混 | UI 写清「应用导出」vs「我的文档」；选切时定 fallback |
| 范围膨胀 | 登录 + OAuth 写盘 + 群通知一次做 | **一次一切**；本文推荐只先 4.1 |
| 打扰 | 每次成功都推群 | 默认偏失败或可开关；文案可静音 |

**依赖**：第 12 / 1.8 导出链路稳定；1.21 notices / 1.22 跑次与触发可复用触点。  
**不依赖**：上云、正式账号体系。
