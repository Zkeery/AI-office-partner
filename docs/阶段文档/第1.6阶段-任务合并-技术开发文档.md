# 第 1.6 阶段技术开发文档｜任务合并

> 配套：`docs/PRD/PRD-1.1.md`、通用技术栈手册、前端技术栈手册。  
> 只覆盖「左侧任务多选合并」；不做归档、不做侧栏删除（详情页删除仍保留）。  
> 开发方法：先写本文档 → 后端 merge API → 前端侧栏多选 → mock 测试。  
> 状态：**已通过**（2026-09-28，产品经理：基本差不多）。  
> 决策：产品经理选 **C 合并**（相对删/归档，后期更好把同主题多次交差收成一条）。

## 一、阶段目标
- 交付：左侧任务列表可进入「管理」勾选 ≥2 条 →「合并」；合成后主任务保留报告，其余任务标「已合并」并从默认列表隐藏。
- 产物：`POST /api/tasks/merge`、侧栏多选 UI、mock 测试。
- 验收：见第十一节。
- 不做：归档箱、侧栏逐条删除、自动用模型重写合并文、跨用户权限。

## 二、技术适配摘要
- 沿用既有 Task 表与 `status` 字段；新增状态值 `merged`，合并指向写在 `plan_json`（不改表结构，避免本机 SQLite 手工迁库）。
- 开发路径：后端服务函数 + API → 前端侧栏。

## 三、技术栈与模型
- 无新模型调用；合并为确定性拼装（报告拼接），不交给 LLM。

## 四、环境与配置
- 端口 3040 / 8040；无新配置项。

## 五、项目结构
- `backend/app/services/tasks.py`：`merge_tasks`、列表默认排除 `merged`
- `backend/app/api/tasks.py`：`POST /api/tasks/merge`、`GET /api/tasks?include_merged=`
- `backend/app/schemas/tasks.py`：`TaskMerge`、出参字段
- `backend/tests/test_tasks.py`：合并用例
- `frontend/lib/api.ts`：`mergeTasks`
- `frontend/app/page.tsx`：侧栏管理/勾选/合并

## 六、数据与状态
- 主任务：保留；`plan_json.merged_from_ids` 记录被并入的 id；若有多份报告，主报告保留最新一份正文，其余以「附录」拼在后面；导出缓存（docx/xlsx/pptx）失效重生成。
- 被并任务：`status=merged`；`plan_json.merged_into_id=主任务 id`；不删文件（仍可 `GET` 详情；默认列表不出现）。
- 主任务选取规则（产品默认）：
  1. 勾选中有报告的，取 `updated_at` 最新的；
  2. 否则取状态为 `succeeded` 且最新的；
  3. 否则取 `created_at` 最新的。
- 禁止：含 `running` / `planning` / 已 `merged` 的任务；少于 2 条。

## 七、API
### `POST /api/tasks/merge`
请求：
```json
{ "task_ids": ["uuid1", "uuid2"] }
```
成功：返回合并后的主任务 `TaskOut`。  
错误：`VALIDATION_ERROR` / `INVALID_STATE` / `TASK_NOT_FOUND`，结构 `{"error":{"code","message"}}`。

### `GET /api/tasks?include_merged=false`
- 默认不返回 `merged`（侧栏顶层只显示主任务）。
- `include_merged=true`：返回被并任务，前端按 `merged_into_id` 挂到主任务下展开。

`TaskOut` 增量：`merged_into_id`、`merged_from_ids`（可选）。

## 八、Prompt
- 无。

## 九、界面切片
- 侧栏标题旁：「管理」→ 出现勾选框；≥2 条勾选后出现「合并」；确认文案说明「保留最新报告，其余收纳到主任务下」。
- 合并成功后选中主任务并自动展开：主任务旁显示 ▸/▾ 与并入条数；展开后**缩进列出**各旧任务标题（可点进查看），不再用底部「显示已合并」把它们散落在列表里。

## 十、测试
- mock：创建 2～3 个 succeeded 任务（含报告）→ merge → 主任务 has_report；其余 status=merged；默认 list 不含它们；`include_merged=true` 可见且带 `merged_into_id`。
- 边界：running 不可并；单条不可并。
- 前端：合并后点主任务 ▸，子项成组出现在其下。

- [x] 主任务报告仍可预览/下载；附录含其他任务报告（若有）
- [x] 不再散落显示「已合并」扁平开关

## 十二、风险
- 多份长报告拼接后导出体积变大——可接受；不做智能去重。
- 用户误合并——本期不提供「拆分」；可用详情页删除主任务（被并项仍在库中标 merged，可再展开查看）。

### 照着点（验收）
1. 打开 http://127.0.0.1:3040 ，进「当前任务」。
2. 左侧点「管理」→ 勾选至少 2 条 →「合并」→ 确认。
3. 默认列表应只见主任务（旁有条数）；点 ▸ 或点主任务，其下应分别列出被并入的旧任务标题。
4. 点某一条子任务，可看该条详情；主任务报告仍可预览/下载。
