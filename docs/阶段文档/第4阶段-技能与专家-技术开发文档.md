# 第 4 阶段技术开发文档｜技能与专家

> 文档同步说明（2026-10-04）：本文为对应阶段的历史设计/验收记录；当前界面、功能范围和操作方式以[当前 PRD](../PRD/PRD-当前版本.md)、[真实工作流实现](融合界面与真实工作流.md)为准。新建任务和自动化均必填 `model_id`，旧无模型参数示例请按[当前 API](../API接口.md)更新后使用。

> 配套：PRD §5.1「技能 / 专家（紧随，同批）」。  
> **技能** = 可复用办事套路；**专家** = 人设 + 默认技能包（薄封装，不另起一套引擎）。  
> **不做**：技能商店上架、用户自定义技能编辑器、多专家协作、定时调用技能。

---

## 一、阶段目标

### 交付
1. 内置 ≥3 个技能、≥2 个专家（JSON 目录，可扩展）
2. `GET /api/skills`、`GET /api/experts` 列表
3. 新建任务可选 `skill_id` 和/或 `expert_id`  
   - 仅选专家 → 使用专家默认技能  
   - 同时选 → 以所选技能为准，专家只提供人设  
4. 计划生成 / 报告撰写 Prompt 注入技能步骤建议与专家人设  
5. 前端：下拉选择专家/技能；选中后展示简介；创建任务带上 ID  

### 验收
- 能看到技能与专家列表  
- 选「竞品调研」或「行业分析专家」创建任务，计划步骤明显贴合该套路（mock 下标题/步骤可区分）  
- 不选手也能走原通用链路  
- 测试覆盖列表与带 skill/expert 创建  

---

## 二、数据（内置目录）

`backend/app/catalog/skills.json` / `experts.json`

技能字段：`id, name, description, plan_hint, report_hint`  
专家字段：`id, name, description, persona, default_skill_id`

---

## 三、API / 任务字段

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/skills` | `{items:[...]}` |
| GET | `/api/experts` | `{items:[...]}` |
| POST | `/api/tasks` | body 增加可选 `skill_id`, `expert_id` |

任务详情回显 `skill_id` / `expert_id`（存于 plan_json 元数据即可，避免破坏已有库）。

---

## 四、明确不做
技能在线编辑、专家对话人格长期记忆、技能市场、子 Agent 分身。

---

## 五、测试
1. skills/experts 非空  
2. 非法 skill_id → 400  
3. 带 skill 创建 → plan_ready，plan 元数据含 skill_id  
4. 仅 expert → 解析到 default_skill_id
