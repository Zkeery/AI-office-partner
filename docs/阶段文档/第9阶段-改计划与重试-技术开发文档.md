# 第 9 阶段技术开发文档｜失败重试与改计划

> 文档同步说明（2026-10-04）：本文为对应阶段的历史设计/验收记录；当前界面、功能范围和操作方式以[当前 PRD](../PRD/PRD-当前版本.md)、[真实工作流实现](融合界面与真实工作流.md)为准。新建任务和自动化均必填 `model_id`，旧无模型参数示例请按[当前 API](../API接口.md)更新后使用。

> 补齐 PRD MVP：「失败时支持重试或改计划再跑」。  
> **不做**：局部段落重写、多版本计划 diff、成功任务强制回滚历史报告。

## 一、目标
- `plan_ready` / `paused` / `failed` 可「改计划」：可改需求文案后重新生成步骤
- `failed`（及已有 `paused`）可「重试 / 继续执行」：沿用确认执行通道
- 改计划后清空旧执行步骤与报告指针，回到 `plan_ready` 待确认

## 二、API
- `POST /api/tasks/{id}/replan`  
  Body：`{ "prompt"?: string, "urls"?: string[] }`  
  状态不合法 → `INVALID_STATE`

## 三、界面
- 计划就绪：确认执行 + 重新生成计划
- 失败：显示错误说明 + 重试执行 + 改计划
- 暂停：继续 + 改计划

## 四、验收
造一份失败或在计划就绪时点「重新生成计划」，应出现新计划并可再确认执行。
