> 文档同步说明（2026-10-04）：本文为对应阶段的历史设计/验收记录；当前界面、功能范围和操作方式以[当前 PRD](../PRD/PRD-当前版本.md)、[真实工作流实现](融合界面与真实工作流.md)为准。新建任务和自动化均必填 `model_id`，旧无模型参数示例请按[当前 API](../API接口.md)更新后使用。

> 配套：`docs/PRD/PRD-1.1.md`、通用技术栈手册。  
> 决策：产品经理「按推荐」→ 1A 真实检索 · 2A 继续 DeepSeek Chat · 3A 写类少搜/短步骤。  
> 状态：**已通过**（2026-09-28，检索 Key 已配通）。

## 一、阶段目标
- 交付：关闭检索模拟（需本机已填 `TAVILY_API_KEY`）；写类场景默认不联网、计划压到约 3 步，研类才检索；健康检查可看「模型/检索是否真实」。
- 不做：换模型厂商、桌面端、新连接器。

## 二、技术适配摘要
- 模型保持 DeepSeek Chat（快、省）。
- 检索：Tavily；无 Key 时**不再静默假结果**，明确报未配置。
- 写类加速：计划后处理 + 执行时跳过检索步。

## 三、技术栈与模型
- 无新依赖；`LLM_MODEL=deepseek-chat` 不变。

## 四、环境与配置
- `SEARCH_MOCK=0`
- `TAVILY_API_KEY=` 由产品经理本机填写（不进仓库、不进对话）
- 改完后需重启后端 8040

## 五、项目结构
- `backend/app/services/office_speed.py`：写类/研类技能划分与计划加速
- `backend/app/services/tasks.py`：生成计划后加速；执行时写类跳过 search
- `backend/app/services/search.py`：无 Key 且非 mock 时明确错误
- `backend/app/prompts/plan.md`：写类/研类步骤约束
- `backend/app/main.py`：health 暴露 mock/配置态（无密钥）
- `frontend/app/page.tsx`：顶栏提示检索是否已配置（可选）

## 六、数据
- 无新表。

## 七、API
- `GET /health` 增量字段：`llm_mock`、`search_mock`、`llm_configured`、`search_configured`、`llm_model`

## 八、写类 vs 研类
- **写类（少搜）**：`weekly_report` / `meeting_minutes` / `email_draft` / `proposal_template` / `customer_reply` / `project_update` / `table_analysis`
- **研类（要搜）**：`competitor_research` / `industry_brief` / `meeting_prep` / `policy_brief` / 未选技能默认

## 九、验收清单
- [ ] `.env` 中 `SEARCH_MOCK=0` 且已填 Tavily Key 后，竞品类报告不再出现「模拟结果 / example.com」
- [ ] 周报/邮件类计划约 3 步、无「联网检索」步；端到端明显快于研类
- [ ] 未配 Tavily 时研类执行给出可读错误，而不是假链接
- [ ] 顶栏或健康检查能看出检索是否已配置
- [ ] mock 自动化测试通过（测试环境仍 `SEARCH_MOCK=1`）
