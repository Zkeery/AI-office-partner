## 1. 需求硬事实（摘自已确认 PRD）

| 项 | 事实 |
| --- | --- |
| 用户 | 个人职场人，本地自用 |
| 核心任务 | 自然语言下调研任务 → 可下载 Markdown 报告 |
| 交互 | 先出计划 → 用户确认 → 执行；可暂停；失败可改计划重试 |
| 工具 | 联网检索、读上传材料、写本机草稿/报告 |
| 确认闸门 | 开始执行；预估费用超约 ¥5；对外发送（MVP 不做发送） |
| 红线 | 不编造无来源；检索不足标待核实；不当训练；不擅自外发 |
| 非目标（MVP） | Word、本地文件夹、技能/专家、定时任务、腾讯生态、桌面/App、多人上云 |

## 2. Harness 五要素映射

| 要素 | 本产品落点 |
| --- | --- |
| 目标 | 产出带结构、尽量带出处的调研报告（Markdown） |
| 观察 | 计划步骤状态、检索摘要、大纲/草稿、费用估算、错误原因 |
| 行动 | 生成计划、检索网页、解析上传文件、起草/改写报告、导出 Markdown |
| 约束 | 计划确认前不执行；超软费用阈值二次确认；禁止无来源事实；上传白名单与大小限制 |
| 知识 | MVP 无独立知识库；靠公网检索 + 用户上传材料 |

## 3. 组件选型（蓝图映射 · 按需）

| 组件意向 | MVP | 理由 |
| --- | --- | --- |
| Agent Loop + Tool Use | ✅ | 多步拆解与工具调用是主链路 |
| Permission / 确认闸门 | ✅ | 计划确认、费用软上限 |
| Task / Todo（步骤状态） | ✅ | 计划步骤可追踪、可恢复 |
| Background / 长任务 | ✅ | 报告生成可达数分钟 |
| SSE 进度 | ✅ | 过程可见 |
| Memory（跨任务长期记忆） | ❌ 暂缓 | MVP 有任务历史即可，不做个性记忆系统 |
| Skills / 专家 | ❌ 紧随 | PRD §5 |
| Cron 定时 | ❌ 后置 | PRD §5 |
| MCP / 多连接器商店 | ❌ 后置 | MVP 仅检索一个插头 |
| RAG / Chroma | ❌ | 无独立知识库需求 |
| Subagent / Teams | ❌ | 单 Agent 足够 |

**说明**：七层图是逻辑职责，不拆成七个服务；单进程 FastAPI + 本机 SQLite + 本地文件即可。

## 4. 逻辑架构（单机）

```
浏览器（3040）
  ↓ HTTP / SSE
FastAPI（8040）
  ├─ 任务 API（创建 / 计划 / 确认执行 / 暂停 / 重试）
  ├─ Agent 运行时（计划生成 → 工具循环 → 成稿）
  │    ├─ tools: web_search, fetch_url, read_upload, write_artifact
  │    └─ gates: plan_confirm, cost_soft_cap
  ├─ 持久化：SQLite（任务/计划/步骤/事件）+ data/uploads + data/artifacts
  └─ 模型适配：用户自备 Key（.env），结构化输出校验
```

## 5. 核心状态机（任务）

`draft` → `plan_ready` →（用户确认）→ `running` ⇄ `paused` → `succeeded` | `failed`  
任意非终态可在失败后 `revise_plan` 回到 `plan_ready`。  
进程重启后从 SQLite 恢复 `running/paused` 任务并继续或标为可恢复。

## 6. 安全与部署边界

- Key 只在项目 `.env`；前端永不持有模型密钥。
- 上传校验扩展名 + 大小 + 安全文件名；PDF/DOCX 只抽取文本。
- 日志不写完整用户正文与 Key。
- 部署：本地自用；不上云、不做企业认证（D9）。
