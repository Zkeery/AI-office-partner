## 运行形态

本机单用户应用：Next.js 16.3.8 / React 19.3 / Tailwind 4.3 前端在 3040，FastAPI / SQLAlchemy 后端在 8040，SQLite 和文件位于本项目运行数据目录。Node 24、Python 3.12，前后端使用锁文件安装。可选 Electron 只是本机 Web 的窗口，不提供独立业务实现。正式公网部署与多用户权限仍未实现。

## 产品与执行定位

产品是面向个人的办公成果应用。当前采用单逻辑 Agent 的 Plan–Execute 工作流：LLM 根据任务要求与材料生成结构化计划，程序校验计划并按步骤调用工具，保存真实执行结果，再由 LLM 组织报告。不同场景复用同一任务控制链；“专家”是调整规划和表达的 Prompt 角色，不是独立运行的 Agent。

自研轻量 Harness 是这条工作流的底层控制层，嵌在现有后端中，负责任务状态、持久化、工具与材料约束、暂停恢复、有限重试以及内部成本控制。它为办公成果交付服务，当前不作为独立平台提供。

执行按已生成并校验的计划推进。材料变化后的重新规划、用户发起的重试和成果改写沿用现有入口；本次定位统一不增加多 Agent 协作或执行中自主重规划需求。

## 页面与业务组织

- `frontend/app/page.tsx` 协调任务、执行、资料库、搜索和导出；普通任务只收任务要求和材料，自动化另收执行时间，不提交模型、技能/专家、预算和材料策略等技术字段。`lib/composer-materials.ts` 根据当前附件推导表格意图，移除材料不遗留旧状态；服务端复用 `detect_scene` 判断场景。
- `components/FusionWorkspace.tsx` 提供暖米色贴纸创作室、响应式导航、输入框和真实成果卡片；`StickerWorkspace.module.css` 定义外观，`FusionWorkspace.module.css` 适配真实任务面板。只复用 `StudioIdentity.tsx` 的静态插画，通过原有业务回调操作相同状态，不引入旧设计页的示例任务和交互。
- `/design-lab/fusion` 和 `/design-lab/lilac` 复用正式页面，刷新任务地址可以恢复所选任务。`/design-lab` 保留为独立设计比较页。
- `/admin` 为独立本机管理页，集中展示模型、技能/专家、预算、材料策略、资料库授权根目录设置和技术统计，普通导航没有入口；密钥由 `.env` 维护，页面不编辑或返回凭据。普通资料库仅浏览、上传和选择材料，不显示本机技术目录路径。模型目录与旧显式 API 字段保留兼容，普通请求由服务端读取管理员 `LLM_*` 默认配置。
- `ReportWorkbench` 显示计算图表、章节改写、版本列表、差异与恢复。首页数据和进度来自真实任务；没有报告时显示空状态。
- 请求序号防止过期列表/搜索/报告响应覆盖新结果。正在运行的任务按秒轮询；服务端保留 SSE 事件接口。

## 创建到交付的数据流

1. 用户描述任务，添加最多三份材料或参考链接；自动化另设执行时间。
2. `POST /api/tasks` 采用管理员默认模型，服务端自动判断场景，由 LLM 生成结构化计划并校验，将具体厂商与型号写入任务元数据；旧显式字段继续兼容。
3. 前端上传材料或挂载选定的资料库文件；有材料时重新规划，确保计划覆盖实际输入。
4. 前端调用确认执行接口，后端检查状态和费用闸门后启动异步任务；费用超限等待用户确认。
5. 程序运行器按已校验计划逐步执行工具。Harness 保存每步状态与结果依据，约束工具和材料访问；未知工具报错，没有输入的可选读取记录跳过。
6. 表格由程序读取全部数据并计算，分析快照写入任务产物；模型使用真实计算结果撰写正文。
7. 报告与版本保存后，前端显示成稿、图表及下载/改写入口。Office 导出从对应正文和快照生成实际文件。

## 服务模块

下列模块共同实现应用所需的轻量 Harness，没有新增独立 Harness 服务或平台接口。

| 模块 | 主要职责 |
| --- | --- |
| `api/tasks.py`、`services/tasks.py` | 创建、规划、异步运行、暂停、重试、材料、合并、归档及导出 |
| `services/models.py`、`services/llm.py`、`services/usage.py` | 配置目录、固定型号、Chat Completions、错误分类/有限重试、逐次用量与预算预留 |
| `services/execution.py`、`core/process_lock.py` | SQLite 原子状态占用、执行令牌、防旧响应覆盖、数据目录单进程锁 |
| `services/table_analysis.py` | CSV/XLSX 全量读取、容量检查、指标/分组/月度/异常与图表数据 |
| `services/reports.py` | 章节、不可变版本记录、差异、恢复及乐观并发检查 |
| `services/xlsx_export.py`、`pptx_export.py` | 原始明细、复算公式、原生图表与分页导出 |
| `api/schedules.py`、`services/schedules.py`、`services/schedule_inputs.py` | 原子触发、持久开始/终态、固定型号、材料快照/最新文件/上游版本、预算和通知 |
| workspace、files、Feishu 相关模块 | 仅附加明确选定材料、同名独立文件、完整文档提取及个人 OAuth 导出 |

普通任务沿用管理员的 `LLM_*` 默认配置，显式兼容请求按已有目录解析；每次创建生成独立任务配置，不修改共享 Settings。新任务固定型号，后续规划、执行、重试和改写沿用；密钥和端点仍从服务端配置读取。历史任务保留兼容路径，不能反推并伪填其实际型号。

## 持久化与状态

SQLite 保存任务、步骤、事件、报告版本、自动化、跑次和 ModelCall 用量。上传、报告/分析快照和自动化材料快照保存到本机数据目录；OAuth token 和通知偏好也在此目录，均不入 Git。启动位于 `backend/`，以保持相对 `DATA_DIR=./data` 位置稳定。进程持有 `.service.lock`，同一数据目录不允许第二个后端 worker 启动。

常规状态为 `draft → planning → plan_ready → running → succeeded`，执行中可暂停或失败。SQLite 条件更新原子占用状态，operation_token 使过期响应/异常无法覆盖新执行。`plan` 与 `replan` 共用状态约束；重启时 planning 转为明确失败可重新规划，running 转为 paused，未完成步骤回到 pending。归档和合并是附加状态。

自动化先原子占用 `active_run_id` 并写入 running 跑次，再创建任务和调用模型。重复触发返回 SCHEDULE_BUSY；终态必须与任务一致，只有 succeeded 记成功；服务中断时跑次恢复为 interrupted 并释放占用。用户继续暂停任务或改写成果，不重写原跑次历史，也不受已结束跑次预算阻断。退出时先取消并等待执行任务，再释放进程锁。执行器仍在单服务进程内，服务关闭期间不运行定时任务，不承诺分布式队列语义。

报告版本以递增序号记录；改写/恢复检查 `expected_version`，冲突返回 409。恢复生成新版本并沿用目标版本的数据快照，不覆盖旧记录。已有数据库通过初始化迁移补充模型字段和报告版本结构，不删除原任务库。

## 计算与集成边界

每次表格分析最多 100,000 行、1,000,000 数据单元格、50 表、每表 512 列；缺公式缓存时明确失败，不运行上传宏或公式。比例和单价使用未加权均值；展示图表可截取分组/月度窗口，Excel 保留完整结果与明细。

普通用户界面保留个人飞书授权与主动导出，移除模型/技能/专家选择、token 预算、材料策略、技术统计及 Webhook 密钥、群通知配置、回调登记和应用身份导出入口。模型与内部技术配置集中至 `/admin`，相关后端实现保留，当前没有多用户登录或后端角色隔离。群通知默认关闭，真发暂缓。

普通文档容量内完整提取，DOCX 按正文次序读取段落/表格/嵌套表格；单文档 60,000 字符、任务文档合计 90,000、合并工具上下文 120,000，超限明确失败。扫描 PDF 无 OCR。选定资料复制为任务快照，挂载失败原子回滚；同名文件用独占创建保留，工具不会搜集未选资料。

自动化绑定用户明确选定的资料路径和最多 3 个链接；材料快照/最新文件与上游成功跑次固定报告版本及哈希由内部配置承担，普通表单不要求选择策略。每跑次材料总数最多 3 份，上游报告占一份。内部额度默认 50,000，已有有效额度保留；每次请求保守预留输入和最大输出 token，厂商返回 usage 后对账，未知用量保留预留。人民币金额按本机配置估算，不是账单。旧缺模型规则不批量启用，在用户主动重新保存时采用管理员默认，原开关保持不变；仅缺额度但已有模型的规则可采用内部默认，不伪造历史型号或用量。

`scripts/backup_restore.py` 在服务停止时锁定并备份 SQLite 与运行文件；恢复只写新目录、校验哈希/完整性、重定位文件路径并关闭恢复副本的自动化。Python 固定 38 项依赖，前端 package-lock 固定依赖；CI 包含后端、前端状态/浏览器回归、构建及全量依赖审计。
