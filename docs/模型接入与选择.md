> 2026-10-04 的错误分类、有限重试、逐次用量与自动化预算验收保留为历史事实，见[修复验收 F09/F12](审查报告/2026-10-04-12项缺口修复验收.md)。本轮按用户最新要求，将模型选择、token 预算等移出普通界面，由管理员配置和服务端默认值承担；不倒填历史实际型号或用量。实现与验证边界见[用户界面精简](阶段文档/用户界面精简.md)、[本轮验收](evidence/2026-10-05-用户界面精简/验收说明.md)。

更新：2026-10-05。普通用户只描述任务和添加材料，不选择模型、技能/专家或预算。服务端沿用管理员 `LLM_*` 默认模型，固定型号供后续调用使用；首批四家显式模型接入保留为管理及旧 API 兼容能力。

## 使用与当前状态

- 正式工作台 `http://127.0.0.1:3040/`：输入任务、添加材料或链接后发送；自动化另设执行时间。普通请求不提交模型、技能/专家、token 预算或材料策略。
- 原融合入口 `/design-lab/fusion` 和原淡紫入口 `/design-lab/lilac` 共用正式工作台。独立本机 `/admin` 展示模型、技能/专家、预算、材料策略、资料库授权根目录设置与技术统计，普通导航无入口；没有新增登录或角色鉴权，也不提供 `.env` 密钥编辑。
- DeepSeek：沿用本项目已有 `LLM_*` 配置，真实调用通过。
- GPT、通义千问、豆包：待配置。服务端保留接入能力与管理目录，没有借用 DeepSeek 密钥或模拟结果冒充这些厂商。
- 原任务没有型号记录时保留历史兼容，不伪造实际型号。旧缺模型自动化不批量启用；用户主动保存时采用管理员默认模型，开关保持原值。仅缺额度但已有模型的规则可采用内部默认 50,000，既有有效额度保留。

## 服务端接入

普通任务的默认模型由维护者在本项目 `.env` 中填写 `LLM_*` 配置，参考本项目 `.env.example`。修改后重启后端。密钥不进入管理页、浏览器、任务元数据或版本记录；无需在聊天或前端表单中提供。下面的独立厂商项继续用于管理与旧显式 API 调用。

| 选择项 ID | API Key | Base URL | 型号配置与初始值 |
| --- | --- | --- | --- |
| `deepseek` | `DEEPSEEK_API_KEY` | `DEEPSEEK_BASE_URL` | `DEEPSEEK_MODEL=deepseek-chat` |
| `openai` | `OPENAI_API_KEY` | `OPENAI_BASE_URL` | `OPENAI_MODEL=gpt-4.1-mini` |
| `qwen` | `QWEN_API_KEY` | `QWEN_BASE_URL` | `QWEN_MODEL=qwen-plus` |
| `doubao` | `DOUBAO_API_KEY` | `DOUBAO_BASE_URL` | `DOUBAO_MODEL` 必须填写账号已开通的模型 ID 或推理接入点 ID |

这些是可配置的首批型号，不表示最新型号。默认端点见 `.env.example`，通义千问与豆包端点应匹配账号所在地域；自定义型号需支持当前 Chat Completions 文本调用协议及参数。管理目录中的「可用」表示配置完整，不等于账户权限、余额或联网状态检查成功。管理员默认配置和旧显式选择均在任务创建时保存具体型号；上游拒绝请求时任务会失败，不自动换厂商。

旧显式厂商目录沿用原兼容规则：`LLM_*` 只有在 URL 的主机名属于匹配的官方厂商且 `LLM_MOCK=0` 时才复用于该选择项，独立厂商配置优先。普通请求直接使用管理员的默认 `LLM_*` 配置。`LLM_MOCK=1` 仅为明确配置的开发模拟，真实配置失败时不会自动回退到模拟。

当前费用估计继续采用 `LLM_PRICE_PER_1K_CNY` 的粗略统一估计，不代表各厂商实际账单或实时价格。

内部记录每次请求的厂商、型号、阶段、尝试次数和状态；厂商返回的 prompt/completion/total token 标为实际用量，没有 usage 的调用标为未知，模拟用量明确区分，技术统计集中在管理页。自动化内部额度默认 50,000，既有有效额度保留；先保守预留输入与最大输出，已知用量对账，未知调用不释放预留。额度不是人民币账单硬上限，普通用户无需填写。

`LLM_MAX_OUTPUT_TOKENS` 默认 4096；`LLM_MAX_ATTEMPTS` 默认 3；`LLM_RETRY_BASE_SECONDS` 默认 0.5。网络/超时、408、429、5xx 有限退避重试；401/403、额度不足、无效请求不盲目重试。空响应、非法 JSON、输出被长度截断分别报错，不静默返回模拟内容。

## 接口与持久化约定

- `GET /api/models`：返回公开的 `id`、`label`、`provider`、`model`、`available`、`status`、`hint`；不返回 Key 或 Base URL。
- `POST /api/tasks` 和 `POST /api/schedules`：普通请求省略 `model_id`，服务端采用管理员默认模型；旧显式字段继续兼容并校验配置。默认缺失返回 `DEFAULT_MODEL_NOT_CONFIGURED`，不选择目录首项、不换厂商或静默模拟。场景由服务端复用 `detect_scene` 判断。`/health` 返回 `default_model_id` 与 `default_schedule_token_budget` 供管理诊断。
- 任务输出增加 `model_id`、`model_name`、`model_label`；保存在现有 `plan_json` 中。规划、重新规划、执行/重试和报告改写均使用任务保存的厂商与型号。
- 创建任务时固定具体型号，之后修改厂商的默认型号不会更换既有任务的型号；密钥和端点仍从服务端当前配置读取。
- 自动化保存 `model_id`、`model_name`、`token_budget`；新记录固定型号，所有跑次传给任务。普通编辑保留已冻结型号和有效额度，管理或旧显式 API 可调整内部配置。PATCH 省略预算保留既有值，显式 `null` 恢复默认 50,000；旧缺模型规则在用户主动 PATCH 且未传模型时采用管理员默认，显式 `model_id: null` 仍返回 422。原开关不变，不自动批量启用；仅缺额度且已有模型时可采用默认 50,000。运行中禁止修改规则；已有 SQLite 表补列，不重建/删除数据。
- 不修改全局共享 Settings；每次按任务生成独立配置，避免不同任务串用模型。
- 公开普通创建请求和历史内部调用均可省略技术选择；旧显式请求继续兼容。密钥始终由服务端环境配置读取，不通过 `/admin` 下发。
