- 原融合入口 `/design-lab/fusion` 和原淡紫入口 `/design-lab/lilac` 已复用正式工作台，均创建真实任务并展示实际报告；模型选择规则相同。旧设计截图属于历史记录。

- GPT、通义千问、豆包：待配置。服务端保留接入能力；用户界面仅显示可用项，管理员完成配置后自动出现在选择器中。没有借用 DeepSeek 密钥或模拟结果冒充这些厂商。
- 原来的任务/自动化没有型号记录，展示「历史配置」，继续遵循旧配置；不会猜测或回填其历史实际型号。

## 服务端接入

在项目 `.env` 中填写对应项，参考根目录 `.env.example`。修改后重启后端并刷新页面。密钥不进入浏览器、任务元数据或版本记录；无需在聊天或前端表单中提供。

| 选择项 ID | API Key | Base URL | 型号配置与初始值 |
| --- | --- | --- | --- |
| `deepseek` | `DEEPSEEK_API_KEY` | `DEEPSEEK_BASE_URL` | `DEEPSEEK_MODEL=deepseek-chat` |
| `openai` | `OPENAI_API_KEY` | `OPENAI_BASE_URL` | `OPENAI_MODEL=gpt-4.1-mini` |
| `qwen` | `QWEN_API_KEY` | `QWEN_BASE_URL` | `QWEN_MODEL=qwen-plus` |
| `doubao` | `DOUBAO_API_KEY` | `DOUBAO_BASE_URL` | `DOUBAO_MODEL` 必须填写账号已开通的模型 ID 或推理接入点 ID |

这些是可配置的首批型号，不表示最新型号。默认端点见 `.env.example`，通义千问与豆包端点应匹配账号所在地域；自定义型号需支持当前 Chat Completions 文本调用协议及参数。列表中的「可用」表示配置完整，不等于账户权限、余额或联网状态检查成功。上游拒绝请求时任务会失败，绝不自动换厂商。

已有 `LLM_*` 只有在 URL 的主机名属于匹配的官方厂商且 `LLM_MOCK=0` 时才复用于该选择项。独立厂商配置优先。`LLM_MOCK=1` 会另列「模拟测试」，必须明确选择；真实模型未配置时不会回退到模拟。

当前费用估计继续采用 `LLM_PRICE_PER_1K_CNY` 的粗略统一估计，不代表各厂商实际账单或实时价格。

## 接口与持久化约定

- `GET /api/models`：返回公开的 `id`、`label`、`provider`、`model`、`available`、`status`、`hint`；不返回 Key 或 Base URL。
- `POST /api/tasks` 和 `POST /api/schedules`：新增必填 `model_id`。缺失、空值、未知 ID 或未配置项返回 422，且不创建记录。现有外部调用方需要同步传入该字段。
- 任务输出增加 `model_id`、`model_name`、`model_label`；保存在现有 `plan_json` 中。规划、重新规划、执行/重试和报告改写均使用任务保存的厂商与型号。
- 创建任务时固定具体型号，之后修改厂商的默认型号不会更换既有任务的型号；密钥和端点仍从服务端当前配置读取。
- 自动化新增可空 `model_id`、`model_name` 数据库列；新记录固定型号，所有跑次传给任务。`PATCH /api/schedules/{id}` 可明确更换模型，不能清空。已有 SQLite 表自动补列，不重建/删除数据。
- 不修改全局共享 Settings；每次按任务生成独立配置，避免不同任务串用模型。
- 历史内部服务调用保留无选择的兼容路径；公开创建接口必须显式选择。
